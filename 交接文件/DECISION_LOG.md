# DECISION_LOG

## D-025 暂停月际叙述压缩实验，继续采用 V4.2 旧算法

* 状态：已确认
* 背景：V4.2 旧月际算法已经完成质量评估；正式报告需要在保证事实可靠的前提下保持可读性。
* 需要解决的问题：部分月际文字将连续变化拆分为较多短阶段，人工复核时需做快速文字判断。
* 实验方案：在原始阶段识别与正式叙述之间增加报告阶段压缩和合并规则，并以 development 样本进行评估。
* 实验结果：压缩实验未稳定减少阶段和句数，且曾出现方向误判、事实重复和文字变长风险。
* 最终采用方案：正式路线继续使用冻结的 V4.2 确定性月际叙述；压缩原型仅保留在独立实验分支，不进入正式版本。
* 采用理由：旧算法的主要趋势、关键事实和确定性统计可靠；当前不足可通过人工快速复核处理，继续维护复杂压缩规则的成本高于业务收益。
* 未采用方案及原因：不合并月际叙述压缩实验，因为其收益尚不稳定，且会引入方向、重复事实和可读性风险。
* 影响范围：不修改质控、重采样、月统计、关键月份计算、Word 章节结构或 Streamlit 业务流程；评估工具保留，但不改变正式算法行为。
* 重新启动条件：真实业务中大量报告需要重复修改；人工修改时间成为明显瓶颈；获得更大规模人工标注数据；或出现更简单且更稳健的压缩方法。

## 使用说明

* 出现以下情况时，应新增决策记录：

  * 项目目标、范围或使用场景发生实质变化；
  * 数据流程、质控规则、统计口径或报告结构发生变化；
  * 多个可选方案经过比较后形成明确结论；
  * 某项方案会持续影响后续代码、测试、文档或项目展示；
  * 原有方案被明确推翻、替代或停止使用。

* 以下内容只应更新 `CURRENT_STATUS.md`，不应新增决策：

  * 当前分支、提交哈希和标签；
  * 一次测试结果；
  * 当前报错或临时缺陷；
  * 最近完成的任务；
  * 某个文件是否已修改；
  * 尚未形成长期影响的一次性操作；
  * 下一步执行顺序发生的小幅调整。

* 决策被推翻时：

  * 不删除原决策；
  * 将原决策状态改为“已替代”或“已否决”；
  * 在原决策中注明替代它的新决策编号；
  * 在新决策中注明其替代的旧决策编号；
  * 保留原决策的背景、理由和问题表现。

* 不得删除仍有解释价值的历史决策。已经失败的方案如果能够说明问题来源、项目迭代逻辑或技术取舍，应继续保留，供后续维护和面试复盘使用。

### D-002 核心分析和报告采用本地确定性规则

* 状态：已确认
* 决策时间：本长对话阶段内，准确日期待确认
* 背景：

  * 曾讨论过使用大模型 API 对报告进行生成或润色；
  * 当前报告曾出现方向识别和阶段判断错误。
* 需要解决的问题：

  * 报告事实应由本地算法还是大模型生成；
  * 如何保证数字、月份、方向和结论可复现。
* 可选方案：

  * 完全由大模型生成报告；
  * 本地算法生成事实，大模型负责润色；
  * 完全采用本地确定性规则；
  * 当前使用本地规则，未来再讨论可选润色层。
* 最终采用方案：

  * 核心数据计算、事实提取和单变量报告使用本地确定性规则；
  * 当前不接入大模型 API。
* 采用理由：

  * 如果结构化事实错误，大模型只会将错误表达得更自然；
  * 本地规则更容易测试、复现和追溯；
  * API 会增加密钥、网络、成本、隐私、失败降级和数字保护等额外复杂度；
  * 当前求职项目不需要依赖大模型才能成立。
* 未采用方案及原因：

  * 完全由大模型生成：无法保证数字和事实稳定；
  * 当前立即增加润色层：会扩大范围，但不能解决底层识别错误。
* 依据：

  * 多轮报告检查表明，主要问题来自阶段识别而非单纯措辞；
  * 用户确认当前交接文件中不保留大模型润色作为既定路线。
* 影响范围：

  * 报告架构；
  * 数据安全；
  * 测试方式；
  * 部署复杂度；
  * 项目面试表述。
* 风险与代价：

  * 本地文本可能具有一定模板感；
  * 复杂语言表达能力受规则范围限制。
* 可否逆转：

  * 可以。
* 重新评估条件：

  * 用户未来明确提出需要语言润色；
  * 本地事实层已经稳定；
  * 能建立数字保护、失败降级和可关闭机制。
* 与其他决策的关系：

  * 与 D-006、D-010、D-012 和 D-013 共同构成确定性报告框架。

### D-003 自动质控与人工复核结合，最终分析统一使用 final_qc_data

* 状态：已确认
* 决策时间：本长对话阶段内，准确日期待确认
* 背景：

  * 自动异常规则可能产生误报；
  * 完全人工处理效率低；
  * 项目需要保留质控过程的可追溯性。
* 需要解决的问题：

  * 哪些记录由系统自动处理；
  * 哪些记录需要人工决定；
  * 后续统计使用哪个数据版本。
* 可选方案：

  * 所有候选异常自动删除；
  * 只提供人工清洗；
  * 自动处理确定性无效值，候选异常交由人工复核；
  * 统计直接使用自动质控结果。
* 最终采用方案：

  * 传感器零值和硬范围外数据由自动规则处理；
  * Hampel 和连续恒定值只生成候选；
  * 人工决定候选点和普通点的保留、删除或恢复；
  * 最终统计、绘图和报告统一使用 `final_qc_data`；
  * 全过程写入最终质控日志。
* 采用理由：

  * 自动规则提高效率；
  * 人工复核降低误删风险；
  * `final_qc_data` 能保证所有后续结果使用同一数据基线；
  * 日志能够支持追溯。
* 未采用方案及原因：

  * 候选异常全部自动删除：误删风险较高；
  * 完全人工清洗：效率低；
  * 直接使用自动质控结果：无法反映人工确认。
* 依据：

  * 项目现有流程和报告结构；
  * 用户对人工确认后再进入计算的要求。
* 影响范围：

  * 质控模块；
  * 人工复核界面；
  * 重采样；
  * 统计；
  * 图件；
  * Word 和 Excel 输出；
  * 日志。
* 风险与代价：

  * 人工复核需要额外操作；
  * 结果会受到人工判断影响；
  * 参数变化后需要重新确认。
* 可否逆转：

  * 可以，但属于核心架构变更。
* 重新评估条件：

  * 出现可靠性更高且经过验证的全自动规则；
  * 实际使用场景不再允许人工参与；
  * 质控业务规则发生变化。
* 与其他决策的关系：

  * 是所有报告和统计决策的前置条件；
  * 与 D-002 的可复现性要求一致。

  * 每个变量单独维护代码；
  * 固定九个变量，并通过变量注册表集中管理；

  * 无限动态变量系统：当前没有必要。
* 依据：

  * 用户明确确认变量固定为九个，不再删减；
  * 项目已有变量注册表结构。
* 影响范围：

  * 页面选择；
  * 数据加载；
  * 质控参数；
  * 图件；
  * Excel；
  * Word；
  * 测试。
* 风险与代价：

  * 新增第十个变量仍需要注册配置；
  * 不同设备或站点可能需要重新核验参数。
* 可否逆转：

  * 可以。
* 重新评估条件：

  * 出现明确的新变量需求；
  * 某变量被业务正式取消；
  * 项目转为更通用的平台。
* 与其他决策的关系：

### D-007 报告内容按 hourly、intraday、monthly 三个尺度组织

* 状态：已确认
* 决策时间：本长对话阶段内，准确日期待确认
* 背景：

  * 固定模板难以区分不同时间尺度的事实；
  * 小时极值、日内周期和月际变化容易混在同一段。
* 需要解决的问题：

  * 报告事实如何分层；
  * 不同尺度的统计信息如何避免重复。
* 可选方案：

  * 全部事实写在一个综合段落；
  * 按图件逐段说明；
  * 按 `hourly → intraday → monthly` 三个尺度独立生成。
* 最终采用方案：

  * 时间变化综合分析固定分为：

    * `hourly`；
    * `intraday`；
    * `monthly`。
  * 各尺度只描述自身负责的事实。
* 采用理由：

  * 能够明确区分主体范围、周期、日变化和月际阶段；
  * 结构统一；
  * 便于测试和维护；
  * 不需要通过随机句式制造差异。
* 未采用方案及原因：

  * 单一综合段落：事实容易混杂；
  * 随机变化句式：不能提高事实准确性。
* 依据：

  * 用户明确要求综合分析采用该顺序；
  * 最新报告均已采用。
* 影响范围：

  * 报告上下文；
  * 叙述生成；
  * Word 排版；
  * 测试。
* 风险与代价：

  * 某些变量在部分尺度上特征不明显，文字可能较通用；
  * 需要控制不同段落之间的重复。
* 可否逆转：

  * 可以，但属于报告长期结构变更。
* 重新评估条件：

  * 报告使用场景要求另一种正式模板。
* 与其他决策的关系：

  * 替代 D-006；
  * 与 D-009、D-010 和 D-012 配套。
