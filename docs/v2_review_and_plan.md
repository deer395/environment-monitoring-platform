# V2 技术与产品审查报告

## 1. 当前 V1 架构概况

V1 已经形成本地 Streamlit 最小闭环：

1. `app.py` 负责本地界面、文件上传、参数选择、结果展示和下载。
2. `src/loaders.py` 读取 Excel，并标准化为 `datetime`、`value`。
3. `src/qc.py` 执行当前质控：日内 2 倍标准差和合理范围。
4. `src/resampling.py` 执行 hourly/daily 平均重采样。
5. `src/anomaly.py` 计算日内距平：小时值减同日均值。
6. `src/metrics.py` 计算温度和水深统计。
7. `src/plotting.py` 输出基础图件。
8. `src/report_tables.py` 生成 Excel 导出表。
9. `src/variable_registry.py` 保存变量元数据，但目前仍偏薄。

V1 的主要问题不是功能缺失，而是后续扩展点还没有完全沉到注册表和配置层。当前代码中仍存在 `depth`、`temperature`、`temperature_monthly`、`depth_daily_range` 等分支硬编码。

## 2. 当前质量控制方法的具体缺陷

当前 `src/qc.py` 的日内 2 倍标准差逻辑是：

1. 按日期分组。
2. 计算日均值和日标准差。
3. 若 `abs(value - daily_mean) >= 2 * daily_std`，设为缺测。

主要缺陷：

1. 对极端尖峰敏感。单个极端值会拉高均值和标准差，使多个次级异常逃过识别。
2. 对非正态分布不稳健。潮汐、水深、温度日变化可能有偏态或周期结构。
3. 对样本量敏感。日内记录少时，标准差不稳定。
4. 误删风险不可视。当前只返回摘要，不记录每个异常点的原因。
5. 缺少人工复核。用户无法先看异常点再确认是否剔除。
6. 合理范围尚未完整配置。`variable_registry.py` 中目前只有 `valid_range: None`，没有 `valid_min` / `valid_max`。

## 3. V2 质量控制方法比较

| 方法 | 适用场景 | 误删风险 | 参数需求 | 可解释性 | 建议 |
|---|---|---|---|---|---|
| 物理合理范围 | 明显超出仪器或环境可能范围的值 | 低到中。范围设太窄会误删真实极值 | 每个变量的 `valid_min`、`valid_max` | 很强 | 必做，作为第一层硬规则 |
| 中位数和 MAD | 单日或窗口内存在尖峰，且分布受异常值污染 | 中。真实突变可能被误判 | 窗口或分组方式、MAD 阈值 | 较强 | 推荐作为核心稳健异常检测 |
| Hampel filter | 高频时序中的孤立尖峰 | 中。快速真实变化可能被删 | 窗口大小、sigma 阈值 | 较强 | 推荐用于温度、水深尖峰检测 |
| 滚动中位数 | 平滑局部趋势，识别局部偏离 | 中。窗口不合适会压制真实周期 | 窗口大小、偏离阈值 | 中 | 可选，用于连续数据局部异常 |
| 相邻时刻变化率 | 识别不合理跳变 | 中到高。风暴、传感器移动等真实事件可能触发 | 每变量最大变化率 | 强 | 推荐作为提示型规则，默认需复核 |
| 连续恒定值/传感器卡死 | 识别长时间无变化或重复值 | 低到中。稳定环境可能误报 | 最小连续长度、最小变化幅度 | 强 | 必做，标记为“疑似卡死” |
| 人工复核 | 边界样本和科学判断 | 低 | UI 支持和日志 | 最强 | 必做，用户确认后再进入计算 |

## 4. 推荐的 V2 质量控制组合

不要把所有算法直接叠加删除。推荐分层、可解释、可复核：

### 4.1 自动剔除层

1. 时间和值解析失败。
2. 物理合理范围外。
3. 明显空值、非数值。

这些规则可解释性强，适合自动设为 NaN。

### 4.2 自动标记层

1. Hampel filter。
2. 中位数 + MAD。
3. 相邻时刻变化率。
4. 连续恒定值/传感器卡死。

这些规则先标记，不默认删除。用户在质控页面确认后再应用。

### 4.3 人工确认层

用户可以：

1. 接受全部建议。
2. 取消某些异常点。
3. 按异常原因筛选。
4. 导出质控日志。

V2 推荐默认组合：

1. 必做：物理合理范围。
2. 必做：Hampel filter，用于孤立尖峰。
3. 必做：连续恒定值检测。
4. 可选：相邻变化率，默认只标记不删除。
5. 可选：MAD 日内或滚动窗口检测，用于对比和评估。

## 5. 质控前后对比界面设计

推荐将质控从 `app.py` 当前侧边栏开关中拆成明确步骤。

流程：

数据上传 → 数据体检 → 质控参数配置 → 原始/质控后对比 → 异常点及原因展示 → 用户确认 → 重采样、统计、绘图和导出

页面设计：

1. 左侧：原始时序图。
2. 右侧：质控后时序图。
3. 原始图高亮异常点。
4. 异常点按原因区分颜色：范围外、Hampel、MAD、变化率、卡死。
5. 顶部显示：原始记录数、缺测数、异常数、质控后有效数。
6. 下方显示异常明细表：时间、原值、变量、原因、规则参数、是否应用。
7. 用户点击“确认质控结果”后，后续统计才使用质控后数据。
8. 支持导出质控日志 Excel。

涉及文件：

1. `app.py`：新增质控步骤和状态管理。
2. `src/qc.py`：返回逐点 QC 标记表，而不只是摘要。
3. `src/plotting.py`：新增可复用的 QC 对比图函数。
4. `src/report_tables.py`：新增 QC 日志导出表。

验收标准：

1. 用户能看到原始和质控后曲线。
2. 异常点可按原因区分。
3. 用户确认前不进入后续计算。
4. 质控日志可导出。

## 6. 绘图系统改进方案

当前 `src/plotting.py` 已有统一尺寸、DPI、字体和网格，但仍存在问题：

1. 日期轴使用 `ConciseDateFormatter`，可能显示英文月份。
2. 中文变量名在 `CHINESE_NAMES` 中硬编码，没有完全来自注册表。
3. 月统计图是单独函数，样式仍与通用时序函数有部分重复。
4. y 轴范围、线型、颜色策略没有由变量注册表控制。

V2 建议：

1. 建立 `PlotTheme` 或 `plot_config`，集中控制字体、字号、线宽、颜色、网格、边距、DPI。
2. 日期格式按跨度自动选择：
   - 大于 2 年：`YYYY/MM`
   - 3 个月到 2 年：`YYYY/MM`
   - 小于 3 个月：`YYYY/MM/DD`
   - 小于 7 天：`MM/DD HH:mm`
3. 禁止英文月份缩写，统一数字格式。
4. 图题、y 轴中文名、单位、y 轴范围从 `variable_registry.py` 读取。
5. 所有图件只调用一个样式入口，不逐图写死。
6. 输出图件默认适合中文正式报告：300 dpi、白底、浅灰网格、中文字体优先。

涉及文件：

1. `src/plotting.py`
2. `src/variable_registry.py`

验收标准：

1. 所有日期轴不出现 Sep、Nov、Mar 等英文月份。
2. 所有图件尺寸、字体、线宽、图例、网格一致。
3. 新增变量时无需改绘图样式代码。

## 8. 潜在风险

1. QC 误删真实极端事件。缓解：默认标记、人工确认、日志可追溯。
2. 参数过多导致用户困惑。缓解：提供默认 profile，高级参数折叠。
3. 变量扩展时口径不一致。缓解：注册表统一定义指标、单位和 QC 参数。
4. 绘图中文字体跨机器不稳定。缓解：字体候选列表和缺字检测。
5. Streamlit 状态复杂化。缓解：把 pipeline 状态拆成小函数，避免在 `app.py` 堆逻辑。
6. 旧 PRD 与当前 V1/V2 决策冲突。缓解：以 `docs/v1_scope.md` 和本 V2 文档为准，后续整理 PRD。

## 11. 推荐下一步

下一步先做 Step 1：重构变量注册表。

原因：

1. QC、绘图、指标和导出都依赖变量元数据。
2. 先把变量配置集中，后续加 QC 规则和新变量才不会继续堆硬编码。
3. 这是低风险改动，不会立即改变现有统计结果。
