## 一、方案 B++ 概述

方案 B++ 将 Sidebar 从"参数栏"升级为"导航 + 参数 + 站点资料中心"，主区域从"Hero + 长页面"变为"紧凑顶部栏 + 四阶段工作区"。

核心变更：
1. 产品标识移至 Sidebar
2. Hero 卡片删除，改为紧凑顶部栏
3. 站点任务信息表单移至 Sidebar
4. 主区域仅保留任务概览 + 质量控制 + 统计分析 + 报告交付
5. 四阶段流程条改为更轻量的表达

## 二、Sidebar 信息架构表

| 区域 | 默认状态 | 使用频率 | 状态摘要 | 用户操作路径 |
|------|----------|----------|----------|-------------|
| 1. 产品标识 | 始终可见 | — | 静态 | 品牌锚点，不可交互 |
| 2. 当前处理变量 | 始终可见 | 高（每次切换变量） | 变量名 + 单位 + QC 确认状态 | 下拉选择 → 主区自动切换 |
| 3. 站点任务信息 | 无站名时展开，有站名时折叠 | 低（设好后不常改） | 折叠行显示当前站点名 | 展开 → 填写表单 → 折叠 |
| 4. 监测数据上传 | 未全部上传时展开，全部上传后折叠 | 高（首次使用每个变量）→ 低（使用后） | 折叠行显示 "N/9" | 展开 → 逐变量上传 → 折叠 |
| 5. 分析时间范围 | 当前变量已上传后显示 | 中（每次上传后可能调整） | 日期范围 | 选择起止日期 |

## 七、站点信息移动后的状态与数据风险

| 风险项 | 影响 | 缓解措施 |
|--------|------|----------|
| 站点名称为空时，用户可能不展开 Sidebar 发现缺失 | 主区域在概览区保留轻量提醒："任务资料缺失: 站点名称未填写" | 提醒始终可见，用户可追溯回 Sidebar |
| `station_info_signature` 计算依赖 `_render_station_task_info` 的返回值 | 将函数调用从 main() 行内改为 Sidebar 渲染内，但返回值仍返回给 main() | 需要重构调用方式：确保信息采集和签名计算不变 |
| Sidebar 内站点信息表单的 widget key 与之前一致 | 如果 key 不变，session_state 路径保持，移动不影响 | 不修改任何 widget key |
| Sidebar 渲染顺序变化可能影响 `_refresh_station_report_title` 回调 | 回调函数读取的是 session_state，不受渲染位置影响 | 确认回调在 Sidebar 中工作正常 |
| 综合报告标题逻辑依赖站点名称填写 | 站点名称从 Sidebar text_input 更新，主区报告标题读取 session_state | session_state 仍为共享状态，不受组件位置影响 |

> 站点信息移至 Sidebar 后，**不删除**原有的 widget key、session_state 存储、`station_info_signature` 签名计算和缓存清除逻辑。仅改变 widget 的渲染位置。
